## Building the `ddnet-libs` for Linux, Windows and macOS

The bundled libraries for the official Linux, Windows and macOS builds are built with
`scripts/compile_libs/gen_libs.sh`, the same script that builds them for Android, iOS
and Emscripten. Every source it uses is pinned by commit in
`scripts/compile_libs/sources.sh`, and the one source that is not a repository is
pinned by SHA-256, so a rebuild uses exactly the code that the last one did.

Local development does not need any of this. Use the libraries from the `ddnet-libs`
submodule, or your system's package manager, as described in
[BUILDING.md](BUILDING.md).

### Linux

All three desktop platforms are cross-compiled from Linux. The Linux libraries
themselves are built in a Debian container rather than on the host, so that they do
not pick up a newer glibc than the oldest distribution DDNet supports.

-	Install the toolchain, the 32 bit development packages, and `nasm`, which x264
	needs:
	```sh
	sudo dpkg --add-architecture i386
	sudo apt update
	sudo apt install build-essential cmake ninja-build git nasm pkg-config python3 \
		autoconf automake libtool m4 gcc-multilib g++-multilib \
		libssl-dev libssl-dev:i386 zlib1g-dev zlib1g-dev:i386 \
		libx11-dev:i386 libxext-dev:i386 libxrandr-dev:i386 libxcursor-dev:i386 \
		libxi-dev:i386 libxss-dev:i386 libxfixes-dev:i386 libxtst-dev:i386 \
		libxkbcommon-dev:i386 libasound2-dev:i386 libpulse-dev:i386 \
		libdbus-1-dev:i386 libudev-dev:i386 libdrm-dev:i386 libgbm-dev:i386 \
		libibus-1.0-dev:i386 libgl1-mesa-dev:i386 libgles2-mesa-dev:i386
	```
-	Build both architectures:
	```sh
	scripts/compile_libs/gen_libs.sh build-linux-libs linux
	```

Note that no curl is compiled for Linux. The client links against a stub generated by
`scripts/generate_fake_curl.py` and loads the real libcurl from the system at runtime.

### Windows

-	Install the mingw-w64 toolchain, `gendef` from `mingw-w64-tools`, `nasm`, and the
	autotools that opusfile's `autogen.sh` needs:
	```sh
	sudo apt install mingw-w64 mingw-w64-tools nasm autoconf automake libtool m4
	```
-	The arm64 libraries are built with [llvm-mingw](https://github.com/mstorsjo/llvm-mingw),
	which Debian does not package. Extract a release somewhere and put its `bin`
	folder on `PATH` **after** `/usr/bin`, so that the x86 and x86\_64 libraries keep
	using the mingw-w64 gcc and only arm64 falls through to llvm-mingw.
-	Install Rust and the Windows targets, for the zlib-rs archive that libpng links
	against:
	```sh
	rustup target add x86_64-pc-windows-gnu i686-pc-windows-gnu aarch64-pc-windows-gnullvm
	```
-	Build all three architectures:
	```sh
	scripts/compile_libs/gen_libs.sh build-windows-libs windows
	```

### macOS

-	Set up [osxcross](https://github.com/tpoechtrager/osxcross) with a macOS SDK and
	build its compiler-rt:
	```sh
	./build.sh
	./build_compiler_rt.sh
	```
-	Put the osxcross `target/bin` folder on `PATH`. If the build fails after an LLVM
	upgrade, rebuild osxcross from scratch (`rm -rf build`, then the commands above).
-	Install `nasm`, the autotools, Rust and the macOS targets:
	```sh
	sudo apt install nasm autoconf automake libtool m4
	rustup target add x86_64-apple-darwin aarch64-apple-darwin
	```
-	SDL does not build against the oldest SDK that osxcross installs, so a newer one
	is selected. Set `OSXCROSS_SDK_VERSION` if the installed SDK is not 15.4, or
	`OSXCROSS_SDK` to point at it directly.
-	Build both architectures and the universal binaries:
	```sh
	scripts/compile_libs/gen_libs.sh build-mac-libs mac
	```
-	The arm64 and universal binaries have to be signed before they are shipped, which
	osxcross cannot do. Run the `codesign` command the script prints on a Mac.

### Updating a library

Change the version and the commit for it in `scripts/compile_libs/sources.sh`
together, then rebuild every platform it is bundled for. Resolve the commit for a tag
with the peeled ref, so that an annotated tag gives the commit and not the tag object:

```sh
git ls-remote https://github.com/curl/curl 'refs/tags/curl-8_8_0^{}'
```

The `VERSION` files in `ddnet-libs` are generated from `sources.sh`, so they do not
have to be updated by hand and cannot disagree with what was built.
